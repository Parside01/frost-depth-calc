# Архитектура проекта

Проект разделен на несколько слоев. Это сделано для того, чтобы расчет, база данных и интерфейс не были смешаны в одном большом файле.

Общая структура:

```text
main.py
frost_depth/
  domain/
  application/
  infrastructure/
  ui/
migrations/
tests/
```

## Точка входа

Файл `main.py` запускает приложение.

Он создает подключение к базе, создает репозитории и передает их в главное окно. В этом файле почти нет бизнес-логики: он только собирает приложение из готовых частей.

## Слой domain

Папка `frost_depth/domain` содержит предметную логику.

Здесь находятся:

- модели данных: населенный пункт, тип грунта, строительный коэффициент, входные и выходные данные расчета;
- сама формула расчета глубины промерзания.

Этот слой не знает про интерфейс, SQLite, SQLAlchemy или карту. Благодаря этому расчет можно тестировать отдельно.

## Слой application

Папка `frost_depth/application` связывает расчет с данными из справочников.

Главный класс здесь - `CalculationService`. Он получает выбранный населенный пункт, выбранный грунт, тип конструкции и температурный диапазон. Потом он достает нужные коэффициенты из репозитория и передает подготовленные данные в калькулятор.

Этот слой отвечает за сценарий "посчитать по выбранным значениям".

## Слой infrastructure

Папка `frost_depth/infrastructure` отвечает за базу данных.

Здесь находятся:

- создание SQLAlchemy engine;
- описание таблиц;
- применение SQL-миграций;
- репозитории для чтения населенных пунктов и справочников.

Важное решение: населенные пункты читаются из базы, но не редактируются через интерфейс приложения. Обновление данных происходит через SQL-файлы в папке `migrations`.

## Слой ui

Папка `frost_depth/ui` отвечает за графический интерфейс.

Здесь находятся:

- главное окно приложения;
- виджет карты;
- HTML, CSS и JavaScript для карты.

UI не считает формулы напрямую. Когда пользователь нажимает кнопку расчета, окно вызывает `CalculationService`, получает результат и показывает его на экране.

## Поток данных

Основной поток выглядит так:

1. `main.py` создает базу через `create_database`.
2. `create_database` применяет миграции.
3. `MainWindow` загружает списки из `SettlementRepository` и `ReferenceRepository`.
4. Пользователь выбирает значения в интерфейсе.
5. `MainWindow` вызывает `CalculationService.calculate_by_values`.
6. `CalculationService` достает коэффициенты и вызывает `FrostDepthCalculator`.
7. `FrostDepthCalculator` возвращает результат.
8. `MainWindow` показывает результат.

## Почему такое разделение удобно

Такое устройство облегчает сопровождение:

- формулу можно менять отдельно от интерфейса;
- структуру базы можно менять через миграции;
- UI можно дорабатывать без переписывания расчета;
- тесты могут проверять расчет и базу отдельно.
