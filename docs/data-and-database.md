# Данные и база данных

Проект использует SQLite-базу данных. Это обычный файл, который хранит страны, регионы, населенные пункты, температуры, координаты и справочные коэффициенты.

Основной файл базы:

```text
data/frost_depth.sqlite3
```

## Миграции

SQL-файлы лежат в папке `migrations/`.

При запуске приложения вызывается `apply_migrations`. Она:

1. создает служебную таблицу `schema_migrations`, если ее еще нет;
2. читает список уже примененных миграций;
3. по порядку выполняет новые `.sql`-файлы;
4. записывает примененную версию в `schema_migrations`.

Это значит, что приложение само доводит локальную базу до актуального состояния.

## Основные таблицы

### countries

Хранит страны.

Главные поля:

- `id` - идентификатор;
- `name` - название страны.

Название страны уникально.

### regions

Хранит регионы внутри стран.

Главные поля:

- `id` - идентификатор;
- `country_id` - ссылка на страну;
- `name` - название региона.

Одинаковый регион не может повторяться внутри одной страны.

### settlements

Хранит населенные пункты.

Главные поля:

- `region_id` - ссылка на регион;
- `name` - название населенного пункта;
- `latitude` и `longitude` - координаты;
- `month_01` ... `month_12` - температуры по месяцам;
- `annual_temperature` - среднегодовая температура.

Для расчета особенно важны 12 месячных температур. Без полного набора месяцев расчет не считается корректным.

### soil_types

Хранит типы грунта и коэффициент грунта.

Примеры:

- крупнообломочные грунты;
- крупные пески;
- мелкие пески и супеси;
- глины и суглинки.

Коэффициент должен быть больше нуля.

### building_coefficients

Хранит строительные коэффициенты.

Коэффициент выбирается по двум признакам:

- конструкция здания;
- температурный диапазон внутри помещения.

Например, для здания без подвала и температуры `5-10` выбирается один коэффициент, а для неотапливаемого помещения другой.

## Как код работает с базой

Описание таблиц находится в `frost_depth/infrastructure/schema.py`.

Запросы находятся в `frost_depth/infrastructure/repositories.py`.

Есть два основных репозитория:

- `SettlementRepository` читает страны, регионы, населенные пункты и ищет ближайший населенный пункт по координатам;
- `ReferenceRepository` читает типы грунта и строительные коэффициенты.

## Read-only подход

В текущей версии приложение не редактирует населенные пункты через интерфейс и не содержит публичных методов добавления, изменения или удаления населенных пунктов в репозитории.

Это осознанное упрощение: данные считаются заранее подготовленными. Если нужно добавить новые населенные пункты или исправить коэффициенты, это делается через новые SQL-миграции.

## Неочевидные детали

SQLite по умолчанию не всегда применяет внешние ключи. Поэтому при подключении код явно выполняет:

```text
PRAGMA foreign_keys = ON
```

Для тестов используется база `:memory:`. Чтобы одна in-memory база не терялась между подключениями внутри теста, применяется `StaticPool`.

Поиск ближайшего населенного пункта использует простую формулу расстояния по широте и долготе:

```text
(latitude - selected_latitude)^2 + (longitude - selected_longitude)^2
```

Это быстро и достаточно понятно, но это не точная географическая дистанция по поверхности Земли.
