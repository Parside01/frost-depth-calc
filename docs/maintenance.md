# Сопровождение проекта

Этот документ описывает, как запускать, проверять и аккуратно изменять проект.

## Запуск приложения

Обычный запуск:

```bash
python main.py
```

При запуске приложение создаст или обновит SQLite-базу `data/frost_depth.sqlite3`.

## Установка зависимостей

Зависимости перечислены в двух местах:

```text
pyproject.toml
requirements.txt
```

Основные зависимости:

- `PySide6`;
- `PySide6-WebEngine`;
- `SQLAlchemy`.

## Запуск тестов

Все тесты:

```bash
python -m unittest discover tests
```

Отдельно расчет:

```bash
python -m unittest tests/test_calculation.py
```

Отдельно база и репозитории:

```bash
python -m unittest tests/test_repository.py
```

## Как обновлять данные

Населенные пункты, температуры, координаты, типы грунтов и коэффициенты должны обновляться через SQL-миграции в папке `migrations/`.

Правильный подход:

1. создать новый `.sql`-файл с новым номером;
2. добавить туда изменения данных;
3. запустить приложение или тесты;
4. убедиться, что новая миграция появилась в `schema_migrations`.

Не стоит менять уже примененные миграции, если база могла быть создана у другого человека. Безопаснее добавить новую миграцию.

## Какие места важно не сломать

### Связь месяцев с расчетом

В таблице `settlements` должно быть 12 месячных температур. Калькулятор ожидает ровно 12 значений.

Если в базе появится неполный набор данных, расчет завершится ошибкой.

### Коэффициенты должны быть положительными

Коэффициенты грунта и здания должны быть больше нуля. Это проверяется и на уровне базы, и на уровне расчета.

### Карта зависит от WebEngine и интернета

Интерфейс карты встроен через `PySide6-WebEngine`. Если эта зависимость не установлена, карта не заработает.

Фон карты загружается с OpenStreetMap. Если нет интернета, могут не отобразиться картографические тайлы.

### Поиск ближайшего пункта приближенный

Поиск ближайшего населенного пункта использует простую формулу по широте и долготе. Для учебного проекта этого достаточно, но для профессиональной геоинформационной точности лучше использовать геодезическую формулу или специализированную библиотеку.

### Миграции разбиваются простым способом

SQL-миграции делятся на команды по символу `;`. Поэтому в миграциях лучше держать простые SQL-команды без сложных процедур и блоков.

## Что можно улучшить позже

Возможные будущие улучшения:

- добавить экран просмотра справочных данных;
- добавить импорт данных из таблицы или CSV;
- добавить более точный расчет расстояния на карте;
- добавить офлайн-карту или локальный источник тайлов;
- собрать приложение в исполняемый файл для пользователя;
- добавить больше тестов на ошибки входных данных.

Эти улучшения не обязательны для текущей версии, но могут быть полезны, если проект будет развиваться дальше.
