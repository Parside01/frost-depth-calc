# Путеводитель по файлам проекта

Этот документ объясняет назначение основных файлов проекта. Уровень описания средний: не построчно, но с ключевыми классами, методами и важными деталями.

## main.py

Точка входа в приложение.

Что делает:

- создает базу через `create_database`;
- создает `SettlementRepository` и `ReferenceRepository`;
- запускает `QApplication`;
- открывает `MainWindow`.

Неочевидный момент: `main.py` не должен содержать расчетную логику. Его задача - собрать приложение из уже готовых частей.

## frost_depth/bootstrap.py

Отвечает за подготовку базы данных.

Главная функция:

```text
create_database
```

Она создает папку для файла базы, если нужно, создает объект `Database` и применяет миграции.

Неочевидный момент: при обычном запуске база находится в `data/frost_depth.sqlite3`, но функция также умеет работать с `:memory:` для тестов.

## frost_depth/domain/models.py

Содержит простые модели данных.

Основные модели:

- `Settlement` - населенный пункт с координатами и температурами;
- `SoilType` - тип грунта и его коэффициент;
- `BuildingCoefficient` - коэффициент здания;
- `CalculationInput` - данные, которые нужны калькулятору;
- `CalculationResult` - результат расчета.

Модели сделаны через `dataclass(frozen=True)`. Это значит, что после создания объект не предполагается изменять.

## frost_depth/domain/calculation.py

Содержит чистую формулу расчета.

Главный класс:

```text
FrostDepthCalculator
```

Он проверяет входные данные, считает сумму отрицательных температур, нормативную глубину и расчетную глубину.

Неочевидный момент: расчет зависит только от входной структуры `CalculationInput`. Он не обращается к базе и не зависит от интерфейса.

## frost_depth/application/services.py

Связывает интерфейс, справочники и расчет.

Главный класс:

```text
CalculationService
```

Метод `calculate_by_values` получает выбранный населенный пункт, id грунта, конструкцию и температурный диапазон. Затем он находит коэффициенты в `ReferenceRepository` и вызывает `FrostDepthCalculator`.

Неочевидный момент: именно этот слой переводит пользовательский выбор из интерфейса в точные числовые коэффициенты.

## frost_depth/infrastructure/database.py

Создает подключение к SQLite через SQLAlchemy.

Главный класс:

```text
Database
```

Обычная база открывается по пути к файлу. Для тестов поддерживается `:memory:`.

Неочевидные моменты:

- для `:memory:` используется `StaticPool`, чтобы тестовая база не исчезала между подключениями;
- при каждом подключении включаются foreign keys через `PRAGMA foreign_keys = ON`.

## frost_depth/infrastructure/schema.py

Описывает таблицы базы данных через SQLAlchemy Core.

Здесь есть таблицы:

- `countries`;
- `regions`;
- `settlements`;
- `soil_types`;
- `building_coefficients`.

Также здесь собран `MONTH_COLUMNS` - список колонок `month_01` ... `month_12`. Он нужен, чтобы не перечислять месяцы вручную в каждом запросе.

## frost_depth/infrastructure/migrations.py

Применяет SQL-миграции из папки `migrations`.

Главная функция:

```text
apply_migrations
```

Она создает таблицу `schema_migrations`, проверяет уже примененные версии и выполняет новые SQL-файлы по порядку.

Неочевидный момент: SQL-файл разбивается по символу `;`. Это подходит для текущих простых миграций, но сложные SQL-конструкции с внутренними точками с запятой потребовали бы более аккуратного парсинга.

## frost_depth/infrastructure/repositories.py

Содержит классы для чтения данных из базы.

### SettlementRepository

Отвечает за населенные пункты.

Основные методы:

- `list_countries`;
- `list_regions`;
- `list_settlements`;
- `get`;
- `find_nearest`;
- `list_nearest`.

Неочевидный момент: репозиторий сейчас read-only. Он читает подготовленные данные, но не добавляет и не удаляет населенные пункты.

### ReferenceRepository

Отвечает за справочники.

Основные методы:

- `list_soil_types`;
- `get_soil_type`;
- `list_building_constructions`;
- `list_temperature_ranges`;
- `get_building_coefficient_by_values`.

Неочевидный момент: строительный коэффициент выбирается не по одному полю, а по паре "тип конструкции + температурный диапазон".

## frost_depth/ui/main_window.py

Главное окно приложения.

Что делает:

- строит форму;
- загружает данные в выпадающие списки;
- показывает месячные температуры;
- реагирует на кнопку расчета;
- связывает карту с выбором населенного пункта.

Важные методы:

- `_load_data` загружает начальные справочники;
- `_load_regions` и `_load_settlements` обновляют зависимые списки;
- `_calculate` запускает расчет;
- `_select_nearest_settlement` выбирает населенный пункт по клику на карте;
- `_update_map_for_selected_settlement` обновляет маркеры карты.

Неочевидный момент: окно хранит словарь `_settlement_by_id`, чтобы быстро получить объект населенного пункта по id из выпадающего списка.

## frost_depth/ui/map_widget.py

Qt-обертка над HTML-картой.

Основные классы:

- `MapBridge` принимает координаты из JavaScript;
- `SettlementMap` показывает карту и передает туда ближайшие населенные пункты.

Неочевидный момент: связь между Python и JavaScript построена через `QWebChannel`. Это позволяет JavaScript вызвать Python-метод после клика по карте.

## frost_depth/ui/map_assets/index.html

HTML-шаблон карты.

Он подключает:

- Leaflet CSS;
- локальный `map.css`;
- Leaflet JS;
- `qwebchannel.js`;
- локальный `map.js`.

В шаблон подставляются начальные координаты и список точек.

## frost_depth/ui/map_assets/js/map.js

JavaScript-логика карты.

Что делает:

- создает Leaflet-карту;
- подключает OpenStreetMap-тайлы;
- добавляет маркеры и подписи;
- обновляет список ближайших населенных пунктов;
- обрабатывает клик по карте;
- отправляет координаты клика в Python через `bridge.selectPoint`.

Неочевидный момент: перед выводом подписей используется `escapeHtml`, чтобы текст названия не воспринимался браузером как HTML.

## frost_depth/ui/map_assets/css/map.css

Стили карты и подписей.

Файл задает высоту карты, шрифт Leaflet-контейнера и внешний вид подписей населенных пунктов.

## migrations/

Папка с SQL-миграциями.

`001_schema.sql` создает таблицы. `002_reference_data.sql` заполняет типы грунтов и строительные коэффициенты. Остальные миграции добавляют населенные пункты, страны, регионы и координатные исправления.

## tests/test_calculation.py

Проверяет формулу расчета.

Тесты подтверждают:

- нормативная и расчетная глубина считаются ожидаемо;
- в индекс промерзания входят только отрицательные месячные температуры.

## tests/test_repository.py

Проверяет чтение данных из базы.

Тесты подтверждают:

- страны, регионы и населенные пункты читаются из миграций;
- населенный пункт можно получить по id;
- ближайший населенный пункт находится по координатам;
- строительный коэффициент выбирается по конструкции и температурному диапазону.

Неочевидный момент: тесты используют in-memory SQLite и иногда добавляют тестовые данные напрямую через SQLAlchemy, не через методы приложения.
